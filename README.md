# Практическая работа 9: управление памятью

## Важно
OPS1 и OPS2 в этом проекте — **демонстрационные**, а не официальные последовательности преподавателя. При получении шаблона/ops1/ops2 замените наборы в `variant_a/main.py` и повторите тесты.

## Запуск

```bash
python3 variant_a/main.py
python3 variant_b/main.py
gcc -std=c11 -O2 -Wall -Wextra variant_c/allocator.c -o variant_c/allocator
./variant_c/allocator | tee results/benchmark.csv
./variant_c/allocator test
gcc -std=c11 -O0 -g variant_c/valgrind_demo.c -o variant_c/valgrind_demo
valgrind --tool=memcheck --leak-check=full ./variant_c/valgrind_demo
```

## A
First Fit отклоняет запрос `F=20` в демонстрационном OPS1: суммарно свободно 30 единиц, но самый большой отдельный свободный блок — 15. Это **внешняя фрагментация**. В таблице и карте памяти смотрите реальные результаты запуска.

## B
Coalescing объединяет соседние свободные участки, повышая вероятность успешного выделения большого непрерывного блока. Buddy System округляет запрос вверх до степени двойки и объединяет только свободные блоки-приятели одного размера с адресами, различающимися соответствующим битом. Цена buddy — **внутренняя фрагментация** из-за округления, а также ограничения на слияние (buddy не гарантирует отсутствие всех отказов из-за внешней фрагментации). Для сравнительной таблицы используется среднее по состояниям **после каждой операции**; внешняя доля `(free-largest)/free`, внутренняя доля `(reserved-requested)/reserved` среди активных выделений. Для fit внутренняя фрагментация в этой модели равна нулю.

## C
Аллокатор использует один `mmap`-регион 64 MiB, список блоков, разбиение, coalescing, `my_malloc`, `my_free`, `my_realloc`; поддерживает first fit и best fit. Метрики CSV: elapsed time (ms), максимальный **измеренный** VmRSS в KiB, внешняя фрагментация на конец сценария. Значение -1 для glibc означает «не измерено», а не отсутствие фрагментации. RSS — пиковое среди периодических замеров, не истинный пик ОС; сравнение с glibc приблизительное и зависит от машины и порядка запусков. Метрика фрагментации после полного освобождения часто 0, поэтому для информативного сравнения желательно дополнительно замерить её в середине сценария.

Сценарии: 1 — много мелких выделений, 2 — чередование alloc/free, 3 — крупные блоки. Повторите замеры и сравните медианы; first fit быстрее на поиске первого подходящего блока, best fit может уменьшать остатки в отдельных шаблонах, но просматривает больше блоков.

Встроенный детектор проверяет double free и остаток `live` (простые утечки). Надёжно обнаружить произвольное чтение/запись после `free` без дополнительных средств он **не может**. `valgrind_demo.c` намеренно содержит use-after-free и утечку; Memcheck должен сообщить `Invalid write` и `definitely lost`. Не запускайте демонстрационный файл как безопасный код.
